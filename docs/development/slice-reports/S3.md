# S3 — Family, invites, roles and multiple babies (in progress)

**Status:** the invite and join flows work end to end against the dev backend code on the local emulators:

- a verified owner invites by code / link / email (14a → 14b → 14c → 14d);
- the invitee joins with the 6-digit code as a temporary identity (15 → 16 → 16b → 16a);
- the invitee sees a caregiver Today with the "Chưa lưu tài khoản" banner, saves the account by email and keeps the same uid (16c → 16d);
- when the owner removes them, the device shows 9d.

The backend is deployed to `child-life-dev`. **Not done:**

- Invite emails wait for the SES keys (owner action). Until then they queue with status `waiting-provider`.
- Universal links on iOS wait for an Apple Developer team. Android App Links are configured for the dev flavor.
- Saving with Google or Apple waits for those providers (S2 owner actions).
- Leaving a family (12g, G-031) is not built.
- Purging the Firestore disk cache on lost access is only partial (P-006).

Checklist rows are ◐, never ☑.

## Built

- **Backend** (deployed to dev in the previous commits)
  - Contracts `packages/contracts/src/family.ts`.
  - Callables in `firebase/functions/src/family.ts`:

    | Callable                                     | Rule                                                                                      |
    | -------------------------------------------- | ----------------------------------------------------------------------------------------- |
    | create / regenerate / revoke invite          | P-020; regenerate kills the old code and link                                             |
    | `emailFamilyInvite`                          | AWS SES, D-020; ≤ 5 emails per invite, ≥ 60 s apart; unsubscribe and suppression          |
    | `previewFamilyInvite` / `acceptFamilyInvite` | lockout after 10 unknown codes per account / network address in 15 min, P-021             |
    | `updateFamilyMember`                         | role, relation, extra rights, "Thời hạn" ending at the end of that day in the baby's zone |
    | `removeFamilyMember`                         | records are kept                                                                          |
    | `claimAnonymousIdentity`                     | P-007                                                                                     |

  - Scheduled jobs: hourly membership expiry; mail retry every 15 min.
  - Pages `/i/{token}` (invite landing with the code) and `/u/{token}` (unsubscribe).
  - Rules: members readable by active members; pending invites by Cùng nuôi only; access end dates enforced at once.

## Verification

- **Emulator Rules and integration tests (TypeScript): 48.**
- **Flutter: 200 tests** (84 new):
  - route guard for the join flow, the temporary identity, lost access and adding a baby;
  - lookup parsing (code / link / foreign host);
  - server document parsing and callable reason mapping;
  - role rules (D-017) and member order;
  - widget tests for 14a (owner and caregiver), 14b, 15, 16, 16a, 17, 16c and read-only Today;
  - 60 goldens: 15 screens and sheets × Light / Night care × vi / en.
- **End-to-end** `integration_test/invite_flow_test.dart` passes on the **iOS simulator (iPhone 17 Pro Max)** and the **Android emulator**. The S2 flow still passes on both. Steps:
  1. A verified owner (seeded over REST) signs in and opens Gia đình.
  2. Invites "Bà · Người chăm sóc", and the pending invite has a 6-digit code.
  3. Emails it: the mail is queued and 14d shows; the pending row appears.
  4. Signs out. "Mã mời" → code → 16 → "Vào ngay" → 16a → caregiver Today with the 16c banner and no Kỷ niệm tab. The membership is checked in Firestore.
  5. 16d "Dùng email" keeps the same uid.
  6. The owner removes the member, so 9d shows on the device. "Về trang chính" leads to 08 (unverified account, no baby).
- **Found and fixed on device:**
  - Toasts crashed when shown from a sheet or route that then closed. They also blocked taps on the buttons beneath them; action-less toasts now let taps through.
  - Routing re-checks the base location when the session changes. "Mã mời" now starts the join flow as the base, so "Vào ngay" no longer bounced back to 15.
  - Pushed pages lost their arguments on router refresh. Flow arguments are now kept per location.

## Needs owner action

1. **AWS SES**, so invite emails leave the queue:
   1. Verify the domain `childlife.app` in SES `ap-southeast-1`.
   2. Add the DKIM CNAMEs, an SPF include for `amazonses.com` and a DMARC record.
   3. Request production access (out of the sandbox).
   4. Create an IAM user limited to `ses:SendEmail`.
   5. Set the keys on dev, then redeploy:

      ```
      firebase functions:secrets:set SES_ACCESS_KEY_ID --project child-life-dev
      firebase functions:secrets:set SES_SECRET_ACCESS_KEY --project child-life-dev
      scripts/deploy.sh dev functions
      ```

   Mail that is already queued is retried automatically.

2. **Apple Developer team**, for iOS universal links (`/i/{token}` opening the app), Sign in with Apple and saving with Apple.
3. **Google provider** (from S2), for "Tiếp tục với Google" on 16b and 16d.
