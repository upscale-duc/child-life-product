## Decisions

**D-043 (owner):** sign-in is email + password or an email magic link. There is no TOTP and no Identity Platform upgrade.

**D-044** fills the remaining A01–A12 gaps:

- **Stray accounts:** an email-link sign-in that creates an account without the `staff` claim deletes that account straight away.
- **Sidebar counts:** open tickets, pending storage requests, and data jobs that are running or failed.
- **User menu (G-079):** language and "Đăng xuất".
- **Storage grants:**
  - +5, +10 and +20 GB are routine.
  - Anything else needs the trưởng nhóm role. Others see the reason and a disabled button (G-080).
  - A decline emails the family a message (G-075).
- **Replies** go by email and need a reason, like every other mutation.
- **A11 family notice:** defaults to the Vietnamese copy, whatever language the staff UI uses. Families see exactly what is typed.
- **Audit target for a re-run:** the DJ code, so A12 search finds it.
- **States:** empty, loading and error states use the existing components (G-078).

## Built

### Backend (deployed to dev)

- **Contract** `packages/contracts/src/staff.ts` (browser-safe):
  - roles `ops` / `support` / `eng` / `lead` and the action matrix (P-121), via `staffCan`;
  - `maskEmail`;
  - request schemas, each with a 3–500-character reason;
  - routine grant amounts;
  - the AI budget.
- **Callables** in `firebase/functions/src/staff.ts`, wired as `staff*` in `index.ts`:
  - The caller comes from the ID-token claims `staff`, `roles` and `name`.
  - Every call checks the role.
  - Every mutation writes an append-only `staffAudit` entry: actor, role, action, category, target, reason, detail.
- **Reads:**
  - `staffBadges`;
  - `staffOverview`: active families, accounts, funnel, multi-carer share, weekly care counts, alerts;
  - `staffTickets` / `staffTicket`: masked email, role, family shape, storage, consented diagnostics, thread;
  - `staffStorageRequests`: `F-XXXX` code, bytes by type, previous grants;
  - `staffJobs`;
  - `staffSystem`: histogram, near-quota families, video queue;
  - `staffAi`: drafts, outcomes, budget, rollout;
  - `staffFlags`;
  - `staffAudit`.
- **Writes:**
  - claim / reply (including the Wi-Fi guide macro) / close a ticket;
  - grant or decline storage: the quota is raised by the grant, the owner is notified in the app, both sides are emailed, and the trưởng nhóm gate applies;
  - re-run a failed deletion from its failed step;
  - set a flag: on/off needs `flags.toggle`, a rollout step needs `flags.rollout`;
  - export the audit log (the export is itself logged).
- **Kill switch and budget:**
  - `createMemory` refuses `uploads-paused` while `media_upload` / `video_upload` is off; queued uploads wait.
  - Story drafts pause with `budget-paused` at 100 % of the monthly AI budget.
- **Indexes:**
  - media (type, status);
  - stories (origin, createdAt);
  - tickets (status, createdAt);
  - audit (category, at);
  - `createdAt` overrides for the collection-group scans.
- **Scripts:**
  - `create-staff.mjs` (owner-run; refuses prod without `CONFIRM_PROD=yes`);
  - `seed-portal-emulators.mjs` (emulator-only test data and staff).

## QA handbook (P-132, 2026-10-11)

"Phát triển › Sổ tay kiểm thử" (`/qa`), built from the owner's reference screenshots.

- **What it shows:** "Bắt đầu" (purpose, smoke vs core, how to run, what each status means, test accounts, bug reports), one page per module with what it does, and every case with its test account, steps, expected result and business-map references.
- **Runs:** "Lượt kiểm thử mới" (build name, Dev / Production, notes); the Smoke and "Tất cả ca" progress bars count cases that are no longer "Chưa chạy"; status counts; "Lưu trữ lượt" makes a run read-only (reopen to record more). The last run is remembered per browser; the address carries `?run=…&case=…` so a case can be linked from a ticket.
- **Cases:** built-in ones ship in `firebase/functions/src/qa-catalog.ts` (ids stable, append only). Kiểm thử, Kỹ thuật and trưởng nhóm add cases (`CARE-Q01`) and edit or archive any case; an edit of a built-in case replaces it on that environment. Search ignores tone marks; filters by level, platform and status; ‹ › walk the filtered list in the case sheet.
- **Roles:** new claim `qa` (Kiểm thử) sees only this page; every other staff role sees it too and may record results and comment. `create-staff.mjs` and `seed-portal-emulators.mjs` (`staff.qa@example.com`) know the role.
- **Server:** `staffQa`, `staffQaCase`, `staffQaUpdate` in `firebase/functions/src/qa.ts`; Firestore `qaCases`, `qaRuns/{run}/results/{case}/comments`, closed to clients by the deny-by-default rules. No family data, so no `staffAudit` entry; results and comments carry the staff name and time.
- **Tests:** `firebase/tests/qa.integration.test.ts` (matrix, runs, archived runs, comments, added and edited cases), `baseline.rules.test.ts` (staff cannot read or write the handbook directly), `firebase/functions/test/qa-catalog.test.ts` (ids, prefixes, schema, refs), `apps/portal/test/qa.test.tsx` (progress, filters, run panel, case sheet, who sees the page).
