# ADR-003 — Two isolated environments, explicit selection everywhere

- **Status:** accepted (2026-10-10)
- **Decision:** `dev` = `child-life-dev`, `prod` = `child-life-prod` (to be created). Mobile flavors `dev`/`prod` with app ids `app.childlife.dev` / `app.childlife`; iOS configurations `Debug|Profile|Release-dev|prod` generated by `apps/mobile/tool/ios_flavors.rb`; Android product flavors. Hosting sites `child-life-<env>-landing` / `-admin` behind `dev.childlife.app`, `admin.dev.childlife.app`, `childlife.app`, `admin.childlife.app`. No default Firebase project in `.firebaserc`; deploys name the environment and prod requires owner approval. Seed scripts refuse prod.
- **Enforcement:** Dart `resolveEnvironment` and web `resolveWebEnvironment` refuse unknown flavors/modes, missing config, config for another project, mismatched app ids and hosts of the other environment. The `ping` callable refuses clients from the other environment. Builds of an environment without config fail (Android google-services, iOS plist copy phase).
- **Consequences:** Prod builds fail until the prod project and its configs exist — intentional.
